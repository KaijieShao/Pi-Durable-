# Disk safety and retention

Every engine tick (one second), and again before preparing a run, checks statfs on both configured filesystems. Below `PI_BOOT_DISK_MIN_FREE` or `PI_TASK_DISK_MIN_FREE` (default 1 GiB each), or if either measurement fails, **all new execution waits**. This includes follow-ups in existing worktrees, merge/recovery checks and evaluator admission. An active run is revoked, terminated and verified through the ordinary finalizer. A required outbox alert and `/status` explain the hold; one transition produces one alert, not an alert per second. Space recovery admits queued work, never automatically resubmits a stopped run. The separate worktree budget remains an admission estimate; reaching that budget alone does not block an existing worktree.

No monitor can prevent a different privileged process instantly consuming the last free byte. If the task volume is already completely full, a final checkpoint may be impossible: termination is still verified, **the worktree stays**, the group freezes and the owner reclaims only disposable data before normal unfreeze/reconciliation. A fully exhausted boot filesystem can also prevent SQLite/outbox persistence. Keep the reserve and monitor it; this is not an exactly-once or disk-loss guarantee.

| Source | Retention and limit |
| --- | --- |
| Task worktrees, build output, writable containers | Normal Coordinator archive removes a worktree only after reconciliation and a confirmed final push/merge. Watchdog verifies stopped containers. Four open worktrees and two execution slots bound concurrency; disk floor bounds growth. Maintenance never traverses a worktree or task database. Tasks 8/9 and their directories are protected in full. |
| Docker images and shared layers | Only explicitly labelled `pi-durable.disposable=true`, unused images older than 7 days are candidates. Protect immutable current, rollback and every frozen-series image ID **and** configured tags. Unknown/unlabelled images remain. `image rm` has no force; Docker retains referenced layers. No blanket `system prune`, volumes prune or container removal. |
| Docker build cache | Unused cache older than 7 days, retaining 2 GB. Rebuildable cache is separate from trusted images. No force removal of referenced image layers. |
| Completed trial bundles/test artifacts | An explicit absolute path under an allowed root, completed timestamp, preserved-report flag and no pin are required. Seven days for trial/test artifacts; 14 days for rollback archives. Unknown, active, mounted, linked or pinned content remains. Each new trial registers its completed disposable bundle; ongoing trial data stays outside the list. Keep final acceptance reports and frozen image manifests pinned. |
| Raw trial stores | Register only a fully stopped, disposable trial bundle after its report is preserved; expire after 24 hours. Original General data/conversations are protected, including Tasks 8/9. No task/PR/head/merge records, pending/failed outbox, command deduplication or recovery records are deleted. |
| Metadata logs | journald: 512 MB, 1 GB free-space reserve, 14-day maximum retention. No message bodies, credentials or raw conversations. Acceptance measurements live in separately pinned evidence bundles. |
| SQLite/WAL | Never clean a live database by unlinking WAL or deleting task/outbox rows. SQLite's normal checkpoint bounds WAL when readers finish. Close read-only evidence transactions promptly; investigate sustained WAL growth. Backups are registered completed archives with a preserved restore checklist, while the newest usable rollback stays pinned. |

The measured disk-full incident in series S1 deliberately filled its separate 4 GiB ext4 test volume; it did not establish that the production Docker cache was large. Record **allocated and apparent bytes** separately for sparse loop images. Measure before deleting; preserve the original evidence and create a new frozen series after runtime changes.

Install `deploy/systemd/pi-durable-retention.{service,timer}` on GCP with a reviewed `/etc/pi-durable/retention.json`. Start with `apply:false`, inspect the candidate report and exact protected paths, then enable the scoped policy. Append every current/rollback/frozen image ID before enabling image retention. Never place a retention root inside a live General data/worktree directory. A cleanup failure is logged separately, preserves the remaining files and never changes a successful merge into a failed task. This local disk worker does not enable or alter remote branch cleanup.

The Linux cleanup worker re-reads `/proc/self/mountinfo` and loop backing-file metadata before each eligible bundle. It retains nested bind mounts (including same-device aliases), their backing paths and attached loop images, even when they otherwise meet the age rule. Unreadable attachment metadata fails closed and reports a separate maintenance error. The real bind/loop regression is opt-in on the isolated Linux VM; a skip on Mac or ordinary CI is not reported as a passed kernel test.
